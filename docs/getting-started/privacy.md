# Privacy & Local Data

FinSight does not operate a hosted service. When you self-host it, financial data is stored on infrastructure you control.

::: tip Your finances stay yours.
Each FinSight user gets a separate SQLCipher database under your server's `/data` volume. Your browser is a viewer, not the vault.
:::

## Where data lives

```text
/data                  # default Docker volume; native dev defaults to ./data
├── users.db            # account registry: usernames, Argon2id verifiers, wrapped DB keys, hashed sessions
├── session.key         # wraps persisted session keys; back this up
└── users/<user-uuid>/
    ├── data.sqlcipher   # this user's ledger, budgets, goals, secrets (LLM keys, SimpleFIN URLs)
    ├── backups/         # manual + pre-migration snapshots
    └── imports/         # authenticated CSV staging
```

- **Per-user encryption.** Each `data.sqlcipher` uses a random 32-byte key generated by `crates/finsight-server::crypto::generate_db_key`. The key is stored only wrapped:
  - under `KEK1 = Argon2id(password, kek_salt)` — password changes re-wrap, not re-encrypt
  - under `KEK2 = recovery key bytes` — the printable recovery key *is* the high-entropy KEK, no KDF

  Password verification uses a **separate** Argon2id PHC string (own salt), so the verifier cannot derive the KEK.
- **Unwrapped keys exist only in server memory.** `users/<uuid>/` runtimes are lazy, single-flighted, and evicted after 30 minutes idle (unless an SSE client is attached).
- **Session cookies** are `HttpOnly`, `SameSite=Lax`, sliding 30-day lifetime. The cookie token’s hash and a key wrapped by `/data/session.key` are persisted; `users.db` never holds plaintext passwords or database keys.

## What is local

- All financial records, budgets, goals, transactions, category centroids, and `agent_memory` rows in `data.sqlcipher`.
- LLM API keys and SimpleFIN access URLs — stored per-user inside that encrypted database, not in a shared server keychain.
- Browser/PWA cache — a seven-day, read-only IndexedDB query cache for offline viewing. It is encrypted when the PWA has a secure context and is purged on logout or authentication failure.

## When data leaves your server

Only when you opt into an external integration:

| Integration | What is sent | When |
|---|---|---|
| Cloud AI (OpenAI-compatible, Anthropic) — auto-categorization | Redacted merchant description + amount of *uncategorized* transactions | Batch run when you trigger or schedule categorization |
| Cloud AI — Copilot | Relevant financial context for the question (`finsight-agent::context::build_context`) | Only when you ask the Copilot |
| SimpleFIN | Stored access URL exchanged with SimpleFIN | Only when you connect and press Synchronize |

Use **Ollama** to keep inference on infrastructure you control — FinSight then sends the same context over your local network, not the internet.

## Opt-in and disclosure

- No provider is configured by default. The Copilot and auto-categorization simply do not run until you add one at **Settings → Agent**, where the data-flow explanation is shown before you save.
- You can change or remove the provider at any time; local data is untouched.
- The server’s `/data` volume is the source of truth. For disaster recovery, back up the **whole** volume so `users.db` and every per-user database stay together. Settings → Data & backups also creates encrypted per-user snapshots on the server.

## What we intentionally do not claim

- We do **not** claim end-to-end encryption between browser and server — the server must hold the unwrapped database key in memory to serve your session. What is true is that the data at rest on disk is SQLCipher-encrypted per user, and that passwords and keys are never stored in plaintext.
- We do **not** claim the browser cache is zero-knowledge — it is a convenience read-cache, encrypted when the secure context allows it, and purged on session end. Assume anyone with your device and an unlocked session can read what the browser has cached.

For deployment security (Tailscale vs Caddy, hardened Compose, cookie flags), see [Self-Hosting](/help/self-hosting) and [Security & Privacy](/help/security).
